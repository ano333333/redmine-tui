ADR 4

Redmine テストデータ初期化と YAML seed 方針

Accepted

Context

redmine-tui は現在、datas/ の YAML fixture を読み込むローカルプロトタイプとして実装されている。一方、コンテナ上の Redmine に投入するテストデータは docker/redmine/seed_test_data.rb に固定値として書かれており、 datas/ の内容とは対応していない。

この状態では、TUI が表示・編集対象としている fixture と、ローカル Redmine で確認できる issue、journal、project、user などがずれる。今後 Redmine 接続を進めるには、datas/ を Redmine 側でも使えるようにし、 少なくとも現在 datas/ に用意している範囲のデータを Redmine DB へ投入できる必要がある。

前提: Redmine の schema は Redmine 本体の Rails migration により作成される。このリポジトリでは schema 定義ではなく、テストデータ投入前の 初期化と seed を扱う。

Decision

Redmine テストデータ投入は、初期化 SQL と Rust 製 seed コマンドに分ける。

1
まっさらのテストデータ状態を用意する SQL
Redmine schema を作成せず、seed 対象テーブルのデータ削除と auto increment のリセットに使う。
2
datas/ の YAML から Redmine DB へ seed する Rust スクリプト
xtask crate の seed-redmine サブコマンドとして実装する。
cargo xtask seed-redmine
ID 方針

Redmine DB 上の issues.id は datas/issues/*.yml の id と一致させる。

既存 DB に同じ ID の issue がある場合は、その issue を seed 対象として更新する。

Redmine の既定 admin / anonymous user を壊さないため、datas/users.yml の user ID は 1000 番台から始める。

境界方針

xtask は TUI 本体 crate の entities、 libs、vos を公開させて再利用しない。

YAML parsing helper と seed 用のデータ構造は xtask 内に閉じる。

cargo xtask

cargo xtask は .cargo/config.toml の Cargo alias で実現する。xtask は workspace member として追加し、 seed-redmine サブコマンドを持つ。

datas/ の YAML 読み込みは Redmine 接続までの暫定機能であり、 将来アプリ本体からは削除される見込みである。
seed では SQL insert/update を構成できればよく、TUI の domain entity struct を構成する必要はない。
Redmine DB への投入都合と TUI 表示用 entity の境界を混ぜない方が、 将来の削除や置き換えが容易である。

Seed 対象

現在 datas/ にある以下の YAML を seed 対象とする。

projects.yml users.yml trackers.yml issue_statuses.yml priorities.yml target_versions.yml categories.yml time_entity_activities.yml issues/*.yml journals/*.yml
親子関係は child_ids から逆算し、子 issue 側の parent_id を設定する。
Issue、journal からの user 参照は、この 1000 番台の user ID を使う。
Redmine 側で必須だが datas/ に存在しない値は、seed 側で決定的に補完する。
補完対象の例は user の login と mail、project identifier、version status、 journalized type などである。

Rationale

source datas/ を source of truth にする

TUI の fixture と Redmine 上の確認データが一致し、Redmine 接続後の表示差分や 保存処理を検証しやすくなる。

cargo Rust の開発体験に合わせる

Rails runner で seed し続ける案より、開発者が cargo で操作できる形の方が 既存のプロジェクト構成に合う。

boundary TUI 本体 crate を library 化しない

seed の目的は Redmine DB に現在の YAML の値を入れることであり、 TUI 内部 entity を構成することではない。

schema Redmine schema は Redmine 自身が管理する

Redmine 全 schema を SQL ファイルとして管理すると version 依存が強くなるため、 このリポジトリではテストデータの初期化と投入だけを扱う。

Consequences

xtask crate には YAML parser crate が追加される。DB への投入は、 生成した SQL を Docker Compose の MySQL service 内の mysql command に渡して実行する。TUI 本体の dependency には seed 専用 dependency を追加しない。
docker/redmine/seed_test_data.rb は今後の主経路ではなくなる。
seed は Redmine DB schema の存在を前提にするため、Rails migration が完了していない状態では失敗する可能性がある。
YAML から Redmine DB へ直接 insert/update するため、Redmine model validation や callback は通らない。
custom field、attachment、workflow permission、watcher は初期実装の対象外とする。

Open Questions

なし。
